Same 42 bytes. Two amounts.

A vault reads a token input’s amount at compile-time offsets. Kaspa allows more than one legal push header for the same payload. The attacker keeps length, template hash, and P2SH and still slides every field. PR 234 (supertypo, 29–30 Aug 2026) proposed pinning headers. It was closed, not merged. v1-rc1 does not include the guard.

Token state the vault thinks it is reading

struct TokenState {
    int amount;       // 8-byte payload
    byte[32] owner;
}

Canonical packing — 42 bytes

08  <8 bytes: amount>     20  <32 bytes: owner>
└── 9 bytes ──────────┘   └── 33 bytes ─────────┘
vault reads amount at bytes 1..9

Hostile packing — still 42 bytes, same template

4c 08  <8 bytes>          1f  <31 bytes: owner>
└── 10 bytes ──────┘      └── 32 bytes ────────┘
10 + 32 = 42. Hash matches. P2SH matches.
vault still reads 1..9 and now gets: 08 + 7 attacker bytes
real collateral = 1.  vault thinks ~2^59.
